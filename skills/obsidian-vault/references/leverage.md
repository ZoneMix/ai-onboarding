# /leverage

Identifies 3-7 high-impact skill domains where focused investment yields disproportionate breakthroughs.

## Usage

```
/leverage
```

## Core Concept

"A true leverage point unlocks progress in 3+ areas simultaneously. If it only helps one thing, it is a task, not leverage."

## Process

### Phase 1: Constraint Mapping

```bash
obsidian daily:read
obsidian search:context query="stuck"
obsidian search:context query="bottleneck"
obsidian search:context query="blocked"
obsidian search:context query="if only"
obsidian search:context query="keep running into"
```

Scan vault for repeated frictions, capability gaps, dependency points, and decision bottlenecks.

### Phase 2: Leverage Detection

Apply 6 detection methods:

1. **Bottleneck Convergence**: skills blocking 3+ domains simultaneously
2. **Adjacent Possible**: 80%-developed capabilities needing the final 20%
3. **Multiplier Models**: decision-changing frameworks that alter many downstream choices
4. **Removal Leverage**: eliminating manual tasks that drain time from high-value work
5. **Relationship Leverage**: deepening connections through domain knowledge
6. **Identity Leverage**: closing gaps between who the vault owner is and who they want to be

### Phase 3: Beyond the Vault

Search for leverage in places the vault has never mentioned:
- Adjacent fields
- Foundational disciplines
- Counter-intuitive sources
- Historical parallels

"The most powerful leverage points are often things the vault has NEVER mentioned."

### Phase 4: Verification

Apply 6 tests to each candidate:

1. **3+ Domain Test**: does it unlock progress in at least 3 areas?
2. **Evidence Test**: does the vault show concrete need?
3. **Feasibility Test**: can it be developed within realistic time constraints?
4. **Counterfactual Test**: what happens if this skill is NOT developed?
5. **Already-Tried Test**: has this been attempted before? What happened?
6. **Compound Test**: does it get more valuable over time?

### Phase 5: Output

Ranked Leverage Map with:
- Development paths for each leverage point
- #1 priority with reasoning
- Surprising outlier (the one that does not look like leverage but is)
- Prerequisite chains (what must come first)
- Anti-leverage list (skills that look useful but are not)

Development paths must be concrete: which resource first, which practice environment, which project to test on, what the first 10 hours address, what the next 40 hours address, what the final 50 hours address.

## Anti-Patterns

- Generic skills ("learn to communicate better")
- Interesting-but-irrelevant domains
- Polishing existing strengths instead of addressing gaps
- 1000+ hour suggestions without phased approach
- Single-domain skills masquerading as leverage
- Vague recommendations without concrete next steps
- Restricting suggestions to vault-mentioned domains only
